## 为什么做 WorkAvatar

在使用 AI 辅助办公的过程中，我们遇到一些实际挑战：

**本地知识的利用** — 企业和个人的大量资料存放在本地文档中，让 AI 有效利用这些资料并不容易。RAG 方案通常需要全量预处理，知识图谱方案前期投入也较大，而简单的关键词搜索又难以覆盖需要跨文档梳理和汇总的场景。我们想试试能不能找到一种更轻量的方式。

**检索结果的有效性** — 直接把搜索结果交给智能体，大段原文和不相关内容容易挤占上下文窗口，影响推理效果。我们希望智能体拿到的是精炼的结论和可追溯的来源，而不是一堆原始文本。

**上手的门槛** — 让资料库跑起来，往往要先花不少时间做向量化、知识抽取、结构化处理。文档越多等待越久，容易让人望而却步。

**数据的隐私** — 合同、报表、内部文档不太适合上传到云端处理，但很多方案都依赖云端服务，敏感数据难免要"过一遍别人的服务器"。

WorkAvatar 的思路是：**让资料库轻量起步、智能体按需深挖、全流程本地运行**。

## 核心功能

### 1. AI 原生本地搜索

内置独立的本地资料库搜索引擎，既能在桌面端直接搜索文件，也能作为检索能力注入数字员工或通过 MCP 服务接入其他智能体。

**全格式混合检索**
- 支持 PDF、Word、Excel、PPT、Markdown、TXT 等主流格式，保留原始章节结构、表格数据和页码定位
- 关键词精确匹配 + 语义相似查找双引擎，可按时间、文件类型筛选
- 文件增删改自动增量索引，无需全量重建

**AI 智能检索**
- 内置独立检索子智能体：接到搜索需求后，自主判断问题类型（找具体信息、解释概念、梳理趋势、综合分析），规划检索路径，多轮补充查找，最终输出核心结论和精准来源
- 整个检索过程在内部闭环完成，尽量减少往主智能体的上下文里塞冗余信息
- LLM 不可用时自动降级为基础检索，保证基本可用

**冷热知识渐进沉淀**
- **零成本启动**：只需指向本地目录，系统构建轻量关键词索引即可使用，无需等待全量向量化
- **越用越精准**：被频繁查阅的文档自动升级处理，补充深度摘要和语义索引，检索和总结能力逐步提升
- **自动瘦身**：长期没人访问的深度处理数据自动降级，节省存储空间
- 精确检索打底、语义能力加持，尽量避免纯语义搜索中"看着相关但实际不对"的情况

**多种使用方式**
- **桌面搜索**：普通搜索快速找文件，AI 搜索获取整理后的结论和来源
- **数字员工内建**：任务中自动调用本地搜索能力，无需手动切换
- **MCP 服务**：支持 Claude Code、Cursor 等智能体直接调用，也能接入自定义 Agent 工作流

### 2. 资料库合集

在目录源自动索引的基础上，可手动挑选文件组成稳定的"合集"作为专题资料集。每个合集自动生成全局摘要与关键主题，数字员工通过渐进式检索（先看合集概览、再查目录、定位段落、读取原文）找到所需知识，减少一次性灌入大量无关内容的情况。每次任务可自由选择不同合集组合，合集与员工不绑定。

### 3. 跨任务记忆

数字员工会记住你的偏好和习惯：任务结束后自动提取用户偏好、决策结论、踩坑经验等持久化记忆，下次任务时按优先级注入。记忆系统具备自动提取、过时清理、精炼合并、重要性分级、容量控制等完整机制，用得越多越了解你。

### 4. 本地化工具链

- **Office 文档生成**：数字员工可直接创建和编辑 Word、PPT、Excel 文档，无需安装 Office
- **互联网搜索**：支持多搜索引擎自动降级，无需 API Key
- **独立工作区**：每个数字员工拥有独立工作区，文件操作安全可控
- **Claude Skills**：支持安装社区技能，按需激活
- **20+ 内置工具**：文件读写、目录管理、代码执行、系统信息等，工作区外操作需用户确认

### 5. 多模型与对比

- 支持任何 OpenAI 兼容接口的 LLM 提供商
- 同时向多个模型提问并排对比回答
- 切换模型重新生成，保留原始回答为分支

## 产品特色

| | WorkAvatar | 常见云端智能体 |
|---|---|---|
| **资料库** | 内置核心能力，知识贯穿全链路 | 通常作为可选插件或依赖云端 RAG |
| **检索模式** | 精确+语义混合，子智能体内部闭环 | 多数直接返回搜索结果 |
| **检索输出** | 结论+溯源，精简上下文占用 | 通常返回原文片段 |
| **启动成本** | 轻量索引即可用，无需全量预处理 | 一般需全量向量化或知识抽取 |
| **持续优化** | 冷热自动沉淀，越用越精准 | 通常需人工维护 |
| **数据隐私** | 全本地运行，数据不出本机 | 多依赖云端处理 |
| **LLM 容错** | LLM 不可用时降级为基础检索 | 多数情况下直接报错 |

## 全本地私有化

文档、索引、模型调用、检索处理全流程在本地运行，数据不会流出本机。API Key 使用系统级加密存储，适合合同、报表、内部文档等敏感资料，也适合内网隔离环境使用。

## 适用场景

- **个人知识管理**：本地资料快速定位，AI 辅助梳理内容、总结要点
- **团队内部资料库**：私有化运行，支撑日常资料查询、业务分析
- **智能体开发**：为自定义 Agent 提供稳定的本地文档检索能力
- **敏感资料处理**：合同、报表、内部文档等不便上云的场景

## 功能一览

- **多格式文档解析**：PDF、Word、Excel、图片（OCR）、Markdown、TXT、HTML
- **智能员工画像**：基于资料库合集内容自动生成员工角色、职责和技能建议
- **自研 Agent 系统**：支持工具调用、流式响应、多步推理（ReAct / PlanExecute / ToolFilter）
- **本地搜索引擎**：混合检索、AI 智能检索、冷热知识沉淀、搜索历史
- **资料库管理**：目录源自动索引、合集手动管理、文档→目录→段落的层级浏览
- **数字员工导入导出**：配置 JSON 或完整包（.avatar），含 SHA-256 校验
- **LLM 调用日志**：全量记录 LLM 交互，便于回溯排查

## 架构概览

项目采用 Electron 双进程架构：

- **主进程**：Node.js 环境，包含所有后端服务——数据库、文件解析、知识处理、搜索引擎、LLM 客户端、Agent 系统等
- **渲染进程**：React 前端，通过 IPC API 与主进程通信
- **共享层**：IPC 通道定义和类型，主进程与渲染进程共享
