# WorkAvatar 实现方案

> 供智能体快速了解项目核心架构与实现。

## 1. 技术架构

**进程模型**：Electron 双进程 — `electron/` 主进程（Node.js）+ `src/` 渲染进程（React）。通过 `contextBridge` 暴露 `window.electronAPI`，IPC 通道按模块定义在 `electron/shared/channels/`。

**技术栈**：
- 前端：React 18 + Ant Design 6 + Zustand + i18next
- 后端：better-sqlite3（WAL 模式）+ OpenAI 兼容 LLM API
- 数据库：主库（员工/技能/LLM配置）+ KMS 独立库（workavatar-kms.db）
- 构建：Vite + electron-builder

## 2. KMS 本地资料库搜索引擎

独立模块，位于 `electron/main/services/kms/`。统一管理**目录源**（自动跟踪）与**合集**（手动挑选），支持独立桌面搜索或作为检索组件接入 Agent。

### 子服务

- **kms-database** — 索引目录、文件注册表、FTS5 全文索引、向量嵌入（sqlite-vec）、冷热数据、合集摘要
- **kms-crawler** — 目录扫描、文件变更检测、增量索引、访问统计
- **kms-search-engine** — FTS5 + 向量语义 + 混合搜索，支持时间范围/扩展名/合集过滤
- **kms-index-manager** — 全量/增量/重建索引、向量嵌入生成、冷热数据升降级、合集深度处理
- **kms-search-agent** — 检索子智能体（查询分类→路径规划→多轮检索→结果提纯）
- **kms-file-reader** — 文件读取、段落/TOC 查询、按偏移/行号定位
- **kms-mcp** — MCP 服务（Streamable HTTP，8 个工具暴露给第三方智能体）
- **kms.service** — 顶层外观服务

### 核心机制

**冷热数据分层**：
- 冷数据：文件名 + 关键词索引 + 轻量摘要（文件头500字符，不调 LLM）
- 热数据：LLM 摘要（150字+关键词+主题）+ 段落索引 + 向量嵌入
- 晋升：30天内搜索命中≥5次或读取≥3次
- 降级：90天无访问

**检索子智能体**（6阶段闭环）：
1. 查询类型识别（locate/concept/trend/analysis）
2. 获取文件清单 + 目录摘要
3. 检索路径规划（1-3组关键词 + 候选文件）
4. 多轮检索执行
5. 信息补充（最多5个文件片段，每段2000字符）
6. 结果提纯（结论≤500字 + 精准溯源：文件路径/页码/行号/偏移）
- LLM 不可用时降级为单次混合检索 + 关键词摘要
- 中间进度通过 `KMS_AGENT_SEARCH_PROGRESS` 事件实时推送

**合集深度处理**（9阶段，非阻塞后台执行）：
文件解析 → 段落切分 → LLM 目录恢复 → 目录章节生成 → 段落摘要 → 文件摘要 → 段落向量化 → 合集摘要 → 合集摘要向量化
- 进度通过 `KMS_INDEX_PROGRESS` 推送，含 `collectionId`/`collectionName`
- 支持取消，所有阶段检查 `AbortSignal`

**MCP 服务**：
- 协议：Streamable HTTP（POST /mcp），兼容 2025-03-26
- 暴露 8 个工具：`kms_list_sources`、`kms_stats`、`kms_search`、`kms_agent_search`、`kms_get_content`、`kms_get_summary`、`kms_get_toc`、`kms_get_paragraphs`
- 30 分钟无活动 session 自动清理

### 前端

`src/pages/KMS.tsx` 三视图切换：

- **搜索视图**（默认）：关键词/语义/混合/AI 四种模式，默认混合搜索；搜索历史内嵌于输入框（仅存元数据）
- **合集管理视图**：卡片式合集列表，详情抽屉含文件清单（展开行懒加载 AI 内容）
- **知识沉淀视图**：文件摘要 Tab + 统计信息 Tab

## 3. Agent 子系统

位于 `electron/main/services/agent/`，LightAgent 框架。

### 核心组件

- **core/base-agent** — 执行循环（`executeLoop`/`executeLoopStream`），最大迭代 100 次，工具超时 30 秒
- **core/agent-context** — 上下文管理 + 事件系统（18种事件）
- **business/employee-agent** — 员工代理，系统提示词注入记忆/合集/技能/规划上下文
- **llm/openai-provider** — OpenAI 兼容 LLM，支持 SSE 流式 + 思考模式 + 向量嵌入
- **memory/memory-manager** — 上下文窗口压缩（sliding_window/summary 等策略）
- **planning/planner** — 任务规划（ReAct/PlanExecute/ToolFilter）
- **tools/** — 工具注册表、分发器、中间件链（超时/重试/日志/结果大小限制）
- **skill-manager** — Claude Skills 技能管理

### 工具清单

**内置工具（20个）**：calculator、date_time、shell_exec（危险命令拦截）、read_file（多格式支持，分段读取）、write_file（工作区外确认）、list_dir、create_folder、delete_item、rename_item、move_item、copy_item、get_file_info、search_files、system_info、env_vars（安全前缀）、web_search（多引擎降级）、web_fetch、json_utils、random_utils、ask_user（confirm/select/input）

**Office 工具（2个）**：office_exec（Node.js 沙箱）、office_guide

**KMS 工具（7个）**：kms_search、kms_agent_search、kms_get_content、kms_list_collections、kms_collection_overview、kms_get_toc、kms_get_paragraphs

## 4. 数字员工系统

### 员工创建

用户选择资料库合集（可选）→ EmployeeProfilingService 加载合集 → LLM 流式分析生成画像 + 技能建议 → 用户确认 → 写入数据库 → 进入工作台。

### 跨会话记忆

- 任务结束后异步提取记忆（启发式预判跳过闲聊）
- 记忆表：`employee_memories`，支持置顶/重要性/主题分类
- 自动精炼：记忆数>50 或 总字符>6400 时触发
- 注入系统提示词，按优先级排序：置顶 > critical > normal > low

### 员工导出

- 配置导出：JSON 格式，支持 skip/overwrite/merge 冲突策略
- 完整包导出：`.avatar` 格式（含 SHA-256 校验）

## 5. 工作台

位于 `src/components/workbench/` + `src/hooks/useEmployeeChat.ts`。

### 核心功能

- **流式对话**：SSE 流式输出，支持思考过程 + 工具调用展示
- **消息操作**：重新生成、切换模型重生成、编辑历史重发、分支任务、消息删除
- **多模型对比**：2-3 个模型并排对比，关闭后聚合为分支
- **极简模式**：去除工具/技能/资料库/记忆等，仅保留基础指令
- **输入增强**：字数统计、快捷命令、图片上传、文件拖拽、合集选择

### 性能优化

- **LRU 消息缓存**：容量 20，长任务切换时避免重复解析
- **消息窗口化**：初始展示 30 条，顶部加载更多
- **组件 memo**：CodeBlock、ThinkingSegment、ToolCallSegment、MultiChatPanel 等
- **流式渲染节流**：useDeferredValue + requestAnimationFrame
- **闭包陷阱修复**：异步回调通过 ref 读取最新 state

### KV Cache 优化

同一任务内历史消息保持不变，仅末尾追加：
- 运行时上下文（记忆/合集/技能/规划）注入系统提示词
- 工具 schema 生命周期内不变，行为通过动态引用（如 `collectionIdsRef.current`）决定
- Agent 缓存键仅含不可变配置（员工ID/供应商ID/模型ID/思考模式）

## 6. 开发约定

### IPC 通道

1. `electron/shared/channels/` 定义通道名和类型
2. `electron/main/ipc/` 实现 handler（使用 `safeHandle` 统一错误处理）
3. `electron/preload/index.ts` 通过 `contextBridge` 暴露 API
4. 前端通过 `window.electronAPI` 调用

### 前端约定

- UI 组件库：Ant Design 6，主题 token 替代硬编码颜色
- 状态管理：Zustand（immer 中间件）
- 国际化：`src/i18n/locales/` 维护 zh-CN / en-US
- 明暗主题：`appearance.store.ts` 管理，组件需适配

### 目录结构

```
electron/
  main/
    services/        # 所有后端服务（单例模式）
    ipc/             # IPC handler
  preload/           # contextBridge API
  shared/            # 共享类型 + IPC 通道常量
src/
  pages/             # 页面组件
  components/        # UI 组件
  hooks/             # 自定义 hooks
  stores/            # Zustand stores
  i18n/              # 国际化
```
